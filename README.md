## ระบบล็อตและ FEFO

ยาแต่ละรายการแยกเก็บเป็น **ล็อต** มีเลขล็อตและวันหมดอายุของตัวเอง
เมื่อจ่ายยา ระบบตัดจาก **ล็อตที่ใกล้หมดอายุที่สุดก่อน** อัตโนมัติ

ตัวอย่างที่ทดสอบจริง: รับเข้า 3 ล็อต (หมดอายุ 2027, 2028, 2030) จ่าย 7 หน่วย
→ ตัดล็อต 2027 จนหมด (5) แล้วต่อล็อต 2028 อีก 2 — ล็อต 2030 ไม่ถูกแตะ

เมนู **"ล็อตและวันหมดอายุ"** แสดงทุกล็อตพร้อมจำนวนวันที่เหลือ
แถวแดง = หมดอายุแล้วหรือเหลือไม่ถึง 30 วัน

ทุกการเคลื่อนไหวบันทึกในตาราง `stock_txn` ตรวจย้อนหลังได้ว่ายาออกจากล็อตไหน เมื่อไหร่ ใครทำ

## ขั้นตอนการจ่ายยา

**นักเรียนสแกน QR** → คำขอสถานะ ⏳ รอจ่ายยา (**ไม่ตัดสต็อก**)
**เจ้าหน้าที่กดปุ่ม "จ่ายยา"** → ตัดสต็อกตอนนั้นตามหลัก FEFO

ถ้านักเรียนแจ้งว่าแพ้ยา จะมีคำเตือนขึ้นก่อนยืนยัน
การยกเลิกรายการที่จ่ายไปแล้วจะคืนของกลับเข้าล็อตเดิมที่ตัดไป

## ใบเบิกยาครู 4 ขั้นตอน

```
1 รออนุมัติ  →  2 อนุมัติแล้ว  →  3 จ่ายยาแล้ว  →  4 ครูรับของแล้ว
   ครูส่งคำขอ      เจ้าหน้าที่อนุมัติ    ตัดสต็อก FEFO     ครูยืนยันผ่าน QR
                  (ยังไม่ตัดสต็อก)
```

ระบบบันทึกว่าใครอนุมัติและใครจ่าย และบังคับลำดับ — ข้ามขั้นไม่ได้
(ยืนยันแล้วว่าเรียก "จ่ายยาจริง" ก่อนอนุมัติจะถูกปฏิเสธ)

## การเปลี่ยนภาคเรียน

คลิกป้าย **"ภาคเรียน x/25xx"** สีม่วงบนแถบด้านบน → เลือกภาคเรียนและปีการศึกษา → บันทึก

ระบบตั้งภาคเรียนเริ่มต้นให้อัตโนมัติตามเดือนไทย
(พ.ค.–ต.ค. = ภาคเรียนที่ 1 · พ.ย.–เม.ย. = ภาคเรียนที่ 2)

### เปลี่ยนแล้วเกิดอะไรขึ้น

| | |
|---|---|
| ข้อมูลภาคเรียนเก่า | **อยู่ครบ ไม่ถูกลบ** ดูย้อนหลังได้จากตัวกรองภาคเรียน |
| แบบคัดกรองสุขภาพ | นักเรียนกรอกใหม่สำหรับภาคเรียนใหม่ — ของเก่าไม่ถูกทับ |
| รายการจ่ายยา / ใบเบิก | ที่บันทึกใหม่จะผูกกับภาคเรียนปัจจุบันอัตโนมัติ |
| ฟอร์ม QR | ดึงภาคเรียนจากระบบเอง ไม่ต้องพิมพ์ QR ใหม่ |
| หัวรายงาน PDF | เปลี่ยนตามภาคเรียนปัจจุบันให้เอง |

หน้าคัดกรองสุขภาพมีตัวกรอง **ภาคเรียน** เพิ่มเข้ามา เลือกดูย้อนหลังได้ทุกภาคเรียน
และหน้าต่างเปลี่ยนภาคเรียนจะแสดงว่าแต่ละภาคเรียนมีข้อมูลคัดกรองและการจ่ายยากี่รายการ

> สิทธิ์เปลี่ยนภาคเรียน: ผู้ดูแลระบบ และเจ้าหน้าที่พยาบาล

## การแสดงผลบนมือถือ

- รองรับตั้งแต่จอ **320px** ถึง Desktop รวมแท็บเล็ตแนวตั้ง/แนวนอน
- เดิมเมนูข้างหายไปเฉยๆ บนมือถือ ตอนนี้เป็น **ปุ่มสามขีด** เปิดเมนูแบบเลื่อนเข้า
- ตารางเลื่อนแนวนอนได้ ไม่ตัดข้อมูลทิ้ง พร้อมข้อความบอกให้เลื่อน
- หน้าต่างกรอกข้อมูลเลื่อนขึ้นจากด้านล่างแบบแอปมือถือ ปุ่มบันทึกตรึงไว้ล่างสุด

## การย้ายข้อมูลเดิม (อัตโนมัติ ปลอดภัย)

ตอนบูตครั้งแรกหลังอัปเดต ระบบจะทำให้เองโดยไม่ลบอะไร:

1. ยอดคงเหลือเดิมของยาแต่ละรายการ → สร้างเป็น **ล็อตตั้งต้น** ชื่อ "ยอดยกมา" พร้อมบันทึกความเคลื่อนไหว
2. ประวัติการจ่ายยาเดิมที่ไม่มีสถานะ → ตั้งเป็น `dispensed`
3. สร้างบัญชี `admin` จากค่า `ADMIN_PASSWORD`
4. เพิ่มคอลัมน์ใหม่ด้วย `ALTER TABLE` แบบไม่ error ถ้ามีอยู่แล้ว

ทดสอบกับฐานข้อมูลเวอร์ชันเก่าแล้ว ข้อมูลยา ประวัติ และการตั้งค่าครบถ้วน

## ข้อจำกัดที่ยังเหลือ

- **Backup ยังเป็นแบบกดดาวน์โหลดเอง** ยังไม่มีสำรองอัตโนมัติตามเวลา
- **ยังไม่มีการเข้ารหัสข้อมูลสุขภาพในฐานข้อมูล** (encryption at rest) — พึ่ง Volume ของผู้ให้บริการ
- **รูปนักเรียนเก็บเป็น base64 ในฐานข้อมูล** ถ้าอัปครบ 3,267 คนไฟล์จะประมาณ 80MB
  เกินโควตา Volume 5GB ยังอีกไกล แต่การสำรองจะช้าลง
- **ยังไม่มี rate limiting** บนหน้าฟอร์ม QR — ป้องกันด้วย form key แล้ว แต่ถ้ากุญแจรั่วจะยิงซ้ำได้
- **ชุดทดสอบเป็น integration test** ยังไม่มี unit test ระดับฟังก์ชันและ E2E ผ่านเบราว์เซอร์จริง
